# A/B Testing Notes

Этот файл фиксирует базовые понятия, которые используются в Experiment Lab.
Проект демонстрационный: выводы относятся к synthetic data, а не к реальному
продуктовому эксперименту.

## Control и Treatment

`control` — группа пользователей, которая видит текущую версию продукта. Она
нужна как baseline: с ней сравнивается новая версия.

`treatment` — группа пользователей, которая видит тестовое изменение. В
проекте это новая версия checkout experience.

Корректный A/B-тест требует, чтобы группы были сопоставимы. В Experiment Lab
это приближенно демонстрируется через deterministic hash-based assignment:
один и тот же `user_id` для одного `experiment_key` всегда попадает в один и
тот же вариант.

## Uplift

Uplift показывает разницу между treatment и control.

```text
absolute uplift = treatment_metric - control_metric
relative uplift = (treatment_metric - control_metric) / control_metric
```

Пример: если conversion rate в control равен `0.10`, а в treatment `0.12`, то:

- absolute uplift = `0.02`;
- relative uplift = `20%`.

Для аналитика uplift важен потому, что p-value сам по себе не говорит, насколько
эффект велик и полезен для бизнеса.

## Confidence Interval

Confidence interval — диапазон неопределенности для оценки эффекта. В проекте
интервал считается для разницы `treatment - control`.

Если confidence interval полностью выше 0, наблюдаемая разница выглядит
положительной. Если полностью ниже 0, treatment выглядит хуже control. Если
интервал пересекает 0, направление эффекта нельзя считать устойчивым.

Важно: confidence interval не гарантирует, что реальный эффект точно находится
внутри конкретного интервала. Это способ показать точность оценки при выбранной
статистической процедуре.

## Когда результат нельзя считать надежным

Результат A/B-теста нельзя считать надежным, если:

- слишком мало пользователей или событий;
- группы сильно несбалансированы;
- есть подозрение на Sample Ratio Mismatch;
- пользователи могли попадать в обе группы;
- метрика выбрана после просмотра данных;
- эксперимент остановили из-за “красивого” p-value без правил остановки;
- confidence interval слишком широкий;
- эффект статистически заметен, но слишком мал для продукта;
- есть сильные выбросы в revenue-метриках;
- проверяется много метрик без поправки на multiple testing;
- synthetic data ошибочно интерпретируют как реальный пользовательский трафик.

В Experiment Lab часть этих рисков описана как ограничение проекта. Это
позволяет честно показать методику без завышения выводов.
